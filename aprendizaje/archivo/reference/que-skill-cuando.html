El ciclo, en orden

#FaseSkillDeja escrito en...
1Alinear entendimiento/grill-me— (acuerdo compartido)
2Planear QUÉ construir/scopedocs/scope/
3Decidir CÓMO (stack, datos, diseño)/architectdocs/specs/
4Que el agente conozca el repo (1 vez)/auditAGENTS.md
5Construir desde la spec/developel código
6Probar la app REAL/check verifydocs/reviews/
7Escribir la suite de tests/testlos tests
8Code review con modelo nuevo/check reviewdocs/reviews/
9Redactar PR / changelog/documentel PR
10Cerrar: reconciliar contexto/syncAGENTS.md, scope
Regla suprema: el estado vive en los archivos del repo, nunca en el chat. Si te pierdes: cierra el chat y abre uno nuevo. Todo está en el repo.

Al terminar una fase (orden de preferencia)

  1. Seguir — si la fase que viene necesita el contexto vivo y el chat sigue liviano.
  2. /clear + chat nuevo — si el estado ya quedó en archivos. El caso normal.
  3. /handoff — si hay contexto valioso que aún no está en archivos.
  4. Subagente — para una tarea pesada que ensuciaría el chat.
  5. /compact — último recurso.
